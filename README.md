# SKYBREAK / スカイブレイク

スマホのタッチ操作で広大な3Dフィールドをワイヤー飛行し、空中のコインやアイテムを集めながら、巨人や戦闘機と戦うアクションゲーム。

> **状態：Stage 1ローカル試作を実装済み（プレイ可能）。**
> 以下の将来設計は維持しつつ、現在はブラウザで遊べる最小の飛行・収集・巨人戦を検証します。

## Stage 1 prototype

- Babylon.js + TypeScript + Viteで、約240m四方の街をローカル生成する一人用ブラウザ試作です。外部3D素材、バックエンド、物理エンジンは使いません。
- 20棟の簡易ビル、12枚のコイン、3 HPのブロックモデル巨人（上半身の弱点）を配置しています。コインを8枚集め、巨人を倒すと `STAGE CLEAR`。落下・場外時は直近の屋上へ戻ります。
- 左の仮想スティックで移動、右側のドラッグでカメラ、`BOOST`、`ATTACK`、`WIRE`を使用します。`WIRE`は現在のプロトタイプの明示的な上書きとして、長押しではなくタップで接続／解除を切り替えます。接続中もブーストと攻撃は使えます。
- PC確認用のフォールバックは WASD、マウスドラッグ、Space（ワイヤー）、Shift（ブースト）、E（攻撃）、R（リトライ）です。照準方向・距離・視線から安定した接続候補を選び、候補と接続中のアンカーをHUDとワールドマーカーで表示します。

### Start / build

```bash
npm install
npm run dev
npm run build
```

ローカル開発サーバーは `http://localhost:4173`（LAN確認時は `http://<このPCのIP>:4173`）で起動します。確認済み範囲はデスクトップブラウザのスモークプレイのみで、実機スマートフォンの入力・FPS・発熱は未確認です。航空機、ショップ、セーブ、体力、多ステージ、チュートリアルは将来設計の範囲に残します。

## 1. 目指す体験

「コインを追っていたら戦闘機につかまり、その勢いで巨人を倒して、気づけば街の反対側まで来ていた」

移動・収集・戦闘を途切れずにつなげる。飛行の上達が、探索の自由度と戦闘の楽しさにつながるゲームを目指す。

### ユーザーが明示した要件

- 3Dゲームにする。
- かなり広いフィールドを自由に飛び回れるようにする。
- 空中に浮くコインやアイテムを拾えるようにする。
- 巨人や戦闘機を相手に戦えるようにする。
- 集中線のようなエフェクトで速度をわかりやすく伝える。
- **スマホのタッチ操作を主軸にする。PC操作を先に完成させる以前の案は、この方針で置き換える。**
- GitHubで管理し、開発はCodexで行う。

以下の操作配置、技術構成、追加要素、数値目標は設計案。試作と実機確認を通じて調整する。

## 2. 対象環境と見た目

- 初期案：スマホのブラウザで動く一人用ゲーム。
- 横画面・両手持ちを基本にする案。
- 三人称視点で、キャラクター、ワイヤー、接続先、敵との距離がわかるカメラを用意する。
- 輪郭がわかりやすいアニメ調3D。集中線、斬撃、衝撃波の表現を統一する。
- PC操作は開発確認や追加の遊び方として扱い、スマホの操作性を基準に設計する。
- ネイティブアプリ化、オンライン対戦、共有ランキングは初期範囲に含めず、必要になった時点で検討する。

## 3. タッチ操作の設計案

| 入力 | 基本動作 |
| --- | --- |
| 左親指の仮想スティック | 地上移動、空中の進行方向調整 |
| 右側の空き領域をスワイプ | カメラ操作 |
| ワイヤーボタンを長押し | 狙っている方向の建物や敵へ接続し、保持する |
| ワイヤーボタンから指を離す | 接続を解除し、勢いを保って飛ぶ |
| ブーストボタン | 空中加速 |
| 攻撃ボタン | ロック対象への攻撃 |

### 操作補助

- 接続可能な点を、視線・進行方向・距離・遮蔽物から選ぶ。接続候補は画面に表示する。
- カメラは進行方向をなめらかに追う。手動操作中は自動追従が邪魔をしないようにする。
- 敵と弱点にロック補助を設け、小さな対象を正確にタップし続けなくても戦えるようにする。
- 左右2本のワイヤーは、初期案では一つのボタンから状況に応じて使い分ける。左右別操作は拡張候補。
- **両親指が操作中でも、飛行に必要な操作が成立することを優先する。** ワイヤー保持中に右親指が使えなくなる点は、自動カメラやボタン上のドラッグ操作などを試して解決する。配置は未確定。
- ボタン同士の干渉、画面端やセーフエリア、指で隠れる範囲を実機で確認する。
- ゲーム操作中の意図しないページスクロールや拡大を防ぎ、複数の指の入力を個別に管理する。
- アプリ切り替え、指の入力キャンセル、画面回転時にワイヤーや移動が押しっぱなしにならないようにする。

## 4. ワイヤー飛行

- 片側の接続によるスイングと旋回。
- ワイヤー解除時に速度を引き継ぐ。
- 高所から急降下し、低い位置に接続して急上昇する。
- 空中ブーストと滑空で、建物の少ない区間も移動できるようにする。
- 両側接続での加速や高度な技は、基本操作が安定した後に追加する。
- 建物だけでなく、巨人・戦闘機・浮遊物にも接続できる方向を目指す。

厳密な物理再現だけに任せず、旋回、接続、速度維持に操作補助を加える。「狙った通りに飛べる」感覚を優先する。

高速移動時の壁抜け、地形への埋まり、ワイヤーの不自然な伸び、障害物を挟んだ接続を検証する。ワイヤーが建物の角へ巻き付く高度な挙動は初期必須にしない。

## 5. フィールド

最終的には複数の地区がつながる広いフィールドを目指す。最初は小さなビル街で移動を検証し、地区を追加して広げる。

| エリア案 | 主な遊び |
| --- | --- |
| 高層ビル街 | 高低差と長いスイングによる高速飛行 |
| 住宅街・路地 | 地面すれすれの飛行、狭い場所の通過 |
| 港・工業地帯 | クレーン、橋、コンテナを使った大ジャンプ |
| 渓谷・ダム | 長距離滑空、壁沿いの移動 |
| 上空・空中要塞 | 戦闘機や浮遊物を乗り継ぐ立体戦闘 |

- 遠くに巨人や空中要塞が見え、探索の目標になる景色を作る。
- 広さだけを増やさず、移動経路、収集物、敵、イベントの密度を調整する。
- 地区単位で読み込みと処理を管理し、近くを詳しく、遠くを簡略化して表示する。
- 最終マップの面積と敵数は、スマホ実機の測定後に決める。

## 6. 収集と報酬

- **コイン**：空中の列が、気持ちよく飛べるルートへ誘導する。装備や外見の購入に使う案。
- **エネルギー**：拾うとブースト回復。うまく飛べば加速をつなげられる。
- **特殊アイテム**：コイン吸引、短時間のワイヤー制限解除、衝撃波など。具体的な効果は拡張時に決める。
- **宝箱ドローン**：逃げる対象を追いかけ、飛行技術で追いつく。
- 巨人の足元、橋の下、狭い通路などの難しいルートに高い報酬を置く。
- コインを拾える範囲には適度な余裕を持たせ、高速飛行中でも収集が成立するようにする。

## 7. 戦闘

**敵は戦う相手であると同時に、新しい移動経路になる。**

### 巨人

- 腕や肩などにワイヤーを接続し、旋回して弱点に近づく。
- 初期は1体・少数の行動・明確な弱点で、飛行から攻撃への流れを検証する。
- 拡張案：腕の動きを加速に利用する、脚にワイヤーを巻いて転倒させる。

### 戦闘機

- 機体に接続して引っ張ってもらい、高速移動する。
- 拡張案：翼へ飛び移る、別の機体へ乗り換える、機体から飛び降りて巨人へ攻撃する。
- 接続中の相対移動やカメラを調整し、画面を見失わないようにする。

### 攻撃案

- **高速斬撃**：接近速度や急降下の勢いを攻撃に利用する。
- **拘束攻撃**：旋回してワイヤーを巻き、引き絞る。
- **誘導攻撃**：ミサイルを回避し、別の敵へ誘導する。
- 低速でも安全に狙える基本攻撃を用意し、最高速を出せないと戦えない設計にはしない。

巨大空中母艦、護衛機、砲台、エンジンの部位破壊は後期の拡張候補。

## 8. 速度の演出

- 加速すると画面の外周に集中線を出す。中央の敵・コイン・接続候補は見やすく保つ。
- 速度に応じて視野角を少し広げ、風切り音を強くする。
- 建物すれすれの通過に風圧音やキャラクターの動きを加える。
- ギリギリ回避時の短いスローと再加速は追加候補。
- 最大加速に衝撃波の輪を加える。
- カメラの揺れ、ぼかし、視野角変化などは調整・無効化できる方向にする。
- 演出の強さより、スマホでの視認性と安定した動作を優先する。

## 9. 探索中のイベントと成長

後期の拡張案：

- 遠くに巨人が出現し、飛行中に迎撃へ向かう。
- 頭上を通る戦闘機の編隊を追いかける。
- リングをくぐると、そのままタイムアタックが始まる。
- 輸送機が落としたアイテムを空中回収する。
- 難しい飛び方で届く場所に収集品を置く。

成長は速度や攻撃力の数値だけでなく、空中ジャンプや新しいワイヤー技など、できる動きを増やす方向を検討する。

## 11. スマホ向け性能方針

- 最初の試作段階から、実際のスマホで入力と描画を確認する。
- 60fpsを目標候補にしつつ、低負荷設定で安定した30fpsを確保する案。対応端末と達成値は未検証。
- 遠景の簡略化、見えない物体の描画省略、同形状のまとめ描画を活用する設計。
- 巨人、戦闘機、弾、コインの処理数を管理し、遠方の敵の更新頻度を落とす。
- 影、描画解像度、パーティクル量を画質設定で調整できるようにする。
- 数分間連続して遊んだ際の発熱、処理落ち、メモリ、ロード時間も測る。
- 機能や性能が検証できていないものを、完成済みとして記載しない。

## 12. 開発順序と確認基準

ユーザーから実装開始の指示を受けた後、以下を一段階ずつ進める。

| 段階 | 作るもの | 確認基準 |
| --- | --- | --- |
| 1：飛行試作 | 小さなビル街、タッチ入力、ワイヤー、追従カメラ、集中線 | スマホの両親指で接続・旋回・解除ができ、飛ぶだけで楽しい |
| 2：収集 | コイン、ブースト、リングのコース | 高速飛行中でも拾え、自然に次のルートへ進める |
| 3：巨人戦 | 巨人1体、弱点、基本攻撃、高速攻撃 | 移動から戦闘がつながり、低速でも戦える |
| 4：空中戦 | 戦闘機、移動する機体への接続 | 飛行する相手につながっても操作とカメラが安定する |
| 5：世界の拡張 | 複数地区、イベント、成長要素、負荷調整 | 広いフィールドを探索でき、スマホで継続して遊べる |

最初の小さな完成版の目標は、**「スマホでビル街を自由に飛べて、コインを拾えて、巨人1体と戦える」**状態。

最終構想を一度に実装せず、操作感を確かめながら広さと機能を増やす。
